# v0.6.0：自适应编排与按效果审批

v0.6.0 把“是否需要子任务”放在“选择哪个模型”之前，并用 Direct、Lite、Full 三档控制审批轮次和总消耗。

## 新默认

| 档位 | 子任务 | 审查 | 修订 |
| --- | ---: | --- | ---: |
| Direct | 0 | 父任务按需验证 | 0 |
| Lite | 最多 1 个 Executor | 父任务目标化验证 | 最多 1 次 |
| Full | 配置上限 | 独立 Reviewer | 配置上限 |

Full 只用于高风险/外部/全局效果、跨系统、真正可并行的工作、发布部署或用户明确要求的完整编排。模型和推理强度只在确定需要委派后选择，父任务模型不变。

## 审批变化

项目内范围明确、可逆的读取、写入、构建和测试由原始任务直接授权。`network_read` 仅对 README 公布的精确审查主机自动放行；任意其他主机、IP literal、userinfo、敏感查询或 fragment 都需要批准。删除、全局/系统写入或安装、密钥/私有数据、认证网络、外部写入或消息、push、生产部署、购买、破坏性迁移与重大范围扩展继续使用精确效果 gate，并可合并为一次清晰的批准请求。

## 兼容性

- 未配置 `orchestration` 的 v0.5 配置自动获得 adaptive 默认值。
- 旧 `network_access` 仍为 gated，不会被重新解释成公共读取。
- 新 Handoff 带有 tier/child/revision 预算；`execute` 和旧 `run` 都执行合同、配置、Handoff 三者的最小迭代上限，旧 Handoff 则从当前路由派生。
- `--approve-handoff` 仍可提供，但只做旧调用的 exact-ID 兼容校验；安全任务不再强制要求它。
- 模型目录、健康预检、同后端 fallback、证据和打包边界保持不变。
- 子任务创建前不再重复展示“父任务模型保持不变”或预告备用模型；只有实际发生替换后才披露原因和真实使用的替代模型。
- Standard 和 Full ZIP 使用排序条目、固定时间戳与固定属性生成；相同文件内容在本地和 CI 中得到稳定的 SHA-256。
- Release 工作流由匹配版本号的 `v*.*.*` 标签触发，并在发布前要求重建产物与仓库内 ZIP、校验清单逐字节一致。

## 证据边界

单元和前向路由测试可证明预算与 gate 规则按代码生效；它们不能证明固定 token 节省比例，也不构成新的 connected CLI 成功。真实节省应在相同质量门槛下按成功率、总 tokens、延迟和成本测量。
